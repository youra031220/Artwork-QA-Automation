# 아트웍 검수 자동화 — 텍스트 추출 MVP

이 프로젝트는 아트웍 PDF에서 **한국어 중심 문구를 추출·재구성하고 PDF 전면의 영문 제품명과 작업정보 GAMME를 서로 교차 확인**하는 Streamlit 앱입니다. OCR 판독 후보와 원본 줄의 위치 정보도 보존합니다. 이 단계에서는 검수 조건 판정과 로고 인식을 구현하지 않았습니다.

## 실행 방법 (Windows)

1. Python 3.10 이상을 설치합니다.
2. [Tesseract OCR](https://github.com/UB-Mannheim/tesseract/wiki)를 설치하고 설치 경로를 Windows PATH에 등록합니다. `kor.traineddata`, `eng.traineddata` 언어팩도 설치합니다.
3. 저장소를 복제한 뒤 터미널에서 실행합니다.

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

4. 브라우저에서 PDF 여러 개를 업로드하고 OCR 범위를 선택합니다. 추출을 마치면 CSV·JSON·TXT 결과 ZIP을 다운로드할 수 있습니다.

## P0 · 승인 문구 구조화와 제품정보 범용화

P0 기능은 기존 한국어/OCR 추출과 별개로 실행합니다. **Excel 업로드 없이** `embedded_reference.py`에 내장된 240개 EN–KO 문구를 자동 로딩하고, `excel_loader.py`가 `phrases`, `rules`, `variants`, `validation_issues`를 생성합니다. D229 영문 `Before rst use`는 `Before first use`로 정정했으며, 그 외 모호한 번역은 임의로 수정하지 않았습니다. 사용자로부터 코드 포함에 대한 보안상 허가를 받았습니다.

- Excel 규칙은 행 단위 문구와 조건 단위 그룹을 구별합니다. 특히 '품질 보증 / 사용법' 카테고리 안의 선택 1개·전체 필수 등 서로 다른 조건을 개별 Rule로 보관합니다.
- 문구 승인 여부는 \`UNVERIFIED\`로 표시합니다. 빈 값, 중복 EN–KO 쌍, 동일 EN 복수 번역, 조건/Remark 모호성을 검토 이슈로 보존합니다.
- \`product_parser.py\`가 \`GAMME / PRODUIT\`와 \`NOM GAMME / DESCRIPTION\` 제작사 양식을 지원합니다. 레인지, CMMF, DOSSIER, 유형, 크기, 용량, 뚜껑, 제조국 선언, 열원, 재질을 추출하고 원문·페이지·좌표를 함께 보관합니다.
- 제조국은 \`MADE IN\` 같은 제조국 선언으로 판단하며 프랑스 본사 주소를 프랑스 제조 증거로 취급하지 않습니다. \`+ CV\`는 뚜껑 유무만 확정하고 유리 소재 여부는 확정하지 않습니다.
- 제품정보 표와 상세 원문 좌표를 화면에서 확인하고 CSV/JSON으로 내보낼 수 있습니다.
- P0는 **최종 아트웍 승인 판정이 아닙니다.** 로고·QR·문구별 합부 판정은 후속 단계입니다.

### 비공개 자료 테스트

### 2026-11-10 P0 QA 오류 대응

Chrome QA에서 보고된 P0 FAIL 가운데 BUG-01~05의 원인을 수정했습니다. **앱 브라우저 재시험 전에는 PASS로 간주하지 않습니다.**

- BUG-01: 제작정보의 라벨과 값이 분리된 디자인에서 같은 행·인접 좌표 및 제품유형 의미를 함께 검증합니다. `+ CV`가 확인되지 않으면 `has_lid=False`로 단정하지 않습니다.
- BUG-02: 제품명 비교는 공통 작업정보 파서를 사용해 프랑스어 법정 문구의 GAMME를 오인하지 않습니다. 전면 제목의 수식어 차이는 REVIEW입니다.
- BUG-03: 한국어 앞 숫자 접두어 및 Euromonitor 인용을 보존하고 불일치는 수치 대조 필요로 표시합니다. OCR만으로 숫자를 확정하지 않습니다.
- BUG-04: 작업정보 값의 실제 좌표를 찾아 증거 박스를 수정합니다.
- BUG-05: 긴 세로 문장은 곡선 제품명으로 취급하지 않아 문장부호를 보존합니다.

비공개 실물 PDF를 GitHub에 올리지 않고 로컬에서 재검증해야 합니다. 합성 회귀 테스트는 `test_p0_regressions.py`를 참조하세요.
## 제품명 교차 검수

- **주 판정:** PDF 패키지 전면의 큰 제품명과 PDF 작업정보 `GAMME` 또는 `NOM GAMME`의 제품명을 비교합니다. 내부 접두어 `G7` 등은 제거합니다.
- 대소문자·구분 기호를 무시한 제품명 철자 일치 시 `OK`, 확실히 다른 철자는 `FAIL`, 위치를 찾지 못하면 `REVIEW`입니다.
- 파일명과 `PRODUIT`의 제품 유형·크기 비교는 참고 정보이며 주 판정에 반영하지 않습니다.
- 모든 추출 항목에 원본 페이지·좌표를 기록하고 PDF 영역 미리보기를 제공합니다.
- 전면의 주변 광고 카피는 추출만 하고, 승인 원문 없이 오탈자 `OK`를 선언하지 않습니다.
- `product_identity_checks.csv/json`을 ZIP에 추가합니다.

## PDF 전체 페이지 좌표 미리보기

- 텍스트 추출 후 파일·페이지를 선택하면 원본 PDF를 전체 페이지로 표시합니다.
- 국문 문단 또는 원본 줄, OCR 확인 문구, 곡선 문구, 전면 영문 제품명, GAMME 및 참고용 PRODUIT에 유형별 색상 박스를 겹쳐 표시합니다.
- 문구 목록에서 특정 항목을 선택하면 그 위치가 노란색으로 강조됩니다.
- 문단별 모드에서는 **원본 줄 각각의 사각형**을 사용하므로 문단 사이의 다른 언어 영역까지 덮지 않습니다.
- 페이지 회전과 렌더링 축척을 반영하며, 원본 추출 좌표를 변경하지 않습니다.
- Streamlit 선택 위젯을 조작해도 분석 결과가 사라지지 않도록 세션에 유지합니다.

## 작동 방식

- PyMuPDF로 PDF의 한국어 텍스트, 원본 블록·줄 번호, 좌표, 글꼴 크기를 가져옵니다.
- 읽을 수 없는 숫자·공백 등이 있을 때 해당 부분을 Tesseract `kor+eng`로 보완합니다.
- **문단 재구성:** 같은 PDF 텍스트 블록의 연속 줄은 좌표·줄 번호·글꼴 크기로 묶습니다. 서로 다른 블록이어도 보증 문구, 코팅 성능 문구, AI 생성 이미지 표시처럼 명확한 이어쓰기 패턴은 추가로 결합합니다. 취급 주의 사항, 분리배출 등 새로운 단락은 분리합니다.
- 원본 줄별 텍스트와 OCR 후보를 그대로 보존합니다. 문단 재구성은 표시용 후처리이며 실제 문구를 수정하지 않습니다.
- **곡선 제품명 결합:** 인접한 회전 텍스트 조각을 각도·좌표·글꼴 크기로 그룹화하여 `프라이팬`, `멀티팬` 등으로 이어 붙입니다. 기존 줄별 원문은 별도 보존합니다.

## 결과 다운로드

- `korean_paragraphs.csv/json/txt`: 문단별 정리 결과
- `korean_only.csv/json/txt`: 원본 줄별 한국어 추출 결과 및 OCR 후보
- `summary.json`: 파일별 요약

## 한계

- 곡선 글자는 각도·좌표가 인접한 조각만 결합하며, 비정형 배치에는 추가 검증이 필요합니다. 임의의 제품명을 추측하여 생성하지 않습니다.
- 문단 재구성은 원본 PDF의 동일 텍스트 블록을 우선 사용하며, 일부 확실한 블록 간 이어쓰기 유형을 지원합니다. 다른 비정형 레이아웃은 여전히 별도로 표시될 수 있습니다.
- OCR 복원 후보는 자동 승인된 문구가 아니며, 특히 숫자와 문장부호는 원본과 대조해야 합니다.
- 로고·QR 검출 및 검수 규칙 판정은 추후 구현 대상입니다.

## 데이터 보안

원본 회사 PDF, 승인 문구 Excel, 생성된 검수 결과, API 키는 저장소에 업로드하지 마세요. 업로드 PDF는 앱 프로세스에서만 처리하도록 설계되어 있으며 서버 배포 시 접근 통제를 별도로 고려해야 합니다.

### 2026-11-10 BUG-03 숫자·영문 출처 회귀 개선

- `extractor.py`: 한국어 여부와 관계없이 모든 원본 PDF 텍스트 객체 및 문자 좌표를 `raw_pdf_evidence.json`으로 내보냅니다. 원본 정상 숫자는 유지하고 OCR 숫자는 자동 부분 삽입하지 않습니다.
- `��%`, `��/��`처럼 한글 앞에 놓인 손상 숫자를 버리지 않고 수치 REVIEW로 유지합니다. 별도 숫자 객체는 근접 좌표 근거로만 연결하며 임의로 값을 채우지 않습니다.
- `Euromonitor International`과 `Limited, Home and Garden 2026`처럼 연속된 두 PDF 줄의 실제 인용 근거를 결합합니다. 출처 일부가 확인되지 않으면 REVIEW로 남깁니다.
- 숫자 패턴은 `40%`, `18/10`, `3배`, `10년`, `1위`, `2025`, `16cm`, `1.7L` 등의 유형을 구분합니다. 정상 `3배`는 단순 OCR 결과가 없다는 이유로 수치 오류 처리하지 않습니다.
- `layout.py`: 원본 수치 경고·OCR 후보·원본 객체 ID·좌표를 문단 결과에 계속 전달합니다. 줄끝 `최대`와 다음 줄 시작 `��%`의 확인 가능한 개행도 결합합니다.
- `app.py`: 문단 표·원본 줄 표·PDF 위치 선택 시 수치 확인 사유와 OCR 후보가 표시되며 CSV/JSON/ZIP에도 정보가 남습니다.
- GitHub Actions: `test_p0.py`, `test_p0_regressions.py`, `test_p0_numeric.py` 및 Python 문법 검사를 자동 실행합니다.

**판정 제한:** GitHub Actions의 합성 데이터 테스트 통과는 실제 배포 Streamlit 앱에서 7개 실물 PDF가 PASS됐다는 의미가 아닙니다. PDF 실물의 최종 판정 및 처리시간은 배포 앱에서 다시 측정해야 합니다. OCR이 숫자를 확정적으로 판독하지 못하면 REVIEW로 남겨 사람이 확인해야 합니다.

### 2026-11-10 P0 잔여 OCR·PDF 근거 표시 개선

- `pdf_overlay.py`: 영문 Euromonitor 출처를 원본 PDF 문자별 좌표로 추가 강조합니다. 서로 떨어진 영문 조각은 별도의 박스로 표시하며, 같은 줄의 다른 언어 번역 출처와 혼동하지 않도록 선택합니다.
- PDF 항목 목록에서 수치 REVIEW는 일반 OCR 확인과 구별하여 `수치 대조 필요`로 표시됩니다.
- `extractor.py`: OCR 영역 위아래 및 우측 여백을 확대하여 `18/10` 문구 후보가 중간에 잘리는 사례를 완화했습니다. 긴 문구의 OCR 후보가 현저히 짧을 때만 블록 판독을 재시도합니다.
- 손상된 한국어 원문은 변경하지 않고 PDF 항목 선택 상세에서 **읽기용 OCR 후보(검증 필요)**를 별도로 보여줍니다. 후보에서 의심스러운 영문 조각이 생기면 원본 대조 경고를 유지합니다.
- 개인/사내 아트웍 PDF는 GitHub에 올리지 않고 합성 좌표 기반 `test_p0_overlay.py`와 기존 회귀 테스트로 보호합니다.

**범위:** OCR은 언제든 잘못 판독할 수 있으므로 후보를 확정 텍스트로 자동 치환하지 않습니다. 실제 Streamlit 배포본에서 7개 PDF 재검증 전까지 OCR 후보 품질과 표시 박스는 최종 PASS 판정할 수 없습니다.
