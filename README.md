# 아트웍 검수 자동화 — 텍스트 추출 MVP

이 프로젝트는 아트웍 PDF에서 **한국어 중심 문구를 추출·재구성하고 PDF 전면의 영문 제품명과 작업정보 GAMME를 서로 교차 확인**하는 Streamlit 앱입니다. OCR 판독 후보와 원본 줄의 위치 정보도 보존합니다. 이 단계에서는 검수 조건 판정과 로고 인식을 구현하지 않았습니다.

## 실행 방법 (Windows)

1. Python 3.10 이상을 설치합니다.
2. [Tesseract OCR](https://github.com/UB-Mannheim/tesseract/wiki)를 설치하고 설치 경로를 Windows PATH에 등록합니다. `kor.traineddata`, `eng.traineddata` 언어팩도 설치합니다.
3. 저장소를 복제한 뒤 터미널에서 실행합니다.

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

4. 브라우저에서 PDF 여러 개를 업로드하고 OCR 범위를 선택합니다. 추출을 마치면 CSV·JSON·TXT 결과 ZIP을 다운로드할 수 있습니다.

## P0 · 승인 문구 구조화와 제품정보 범용화

P0 기능은 기존 한국어/OCR 추출과 별개로 실행합니다. 로컬 Streamlit에서 사내 검수 기준 Excel을 직접 업로드하면 \`excel_loader.py\`가 원본 파일을 바꾸지 않고 \`phrases\`, \`rules\`, \`variants\`, \`validation_issues\`를 생성합니다. 업로드 데이터는 공개 저장소에 포함하지 않습니다.

- Excel 규칙은 행 단위 문구와 조건 단위 그룹을 구별합니다. 특히 '품질 보증 / 사용법' 카테고리 안의 선택 1개·전체 필수 등 서로 다른 조건을 개별 Rule로 보관합니다.
- 문구 승인 여부는 \`UNVERIFIED\`로 표시합니다. 빈 값, 중복 EN–KO 쌍, 동일 EN 복수 번역, 조건/Remark 모호성을 검토 이슈로 보존합니다.
- \`product_parser.py\`가 \`GAMME / PRODUIT\`와 \`NOM GAMME / DESCRIPTION\` 제작사 양식을 지원합니다. 레인지, CMMF, DOSSIER, 유형, 크기, 용량, 뚜껑, 제조국 선언, 열원, 재질을 추출하고 원문·페이지·좌표를 함께 보관합니다.
- 제조국은 \`MADE IN\` 같은 제조국 선언으로 판단하며 프랑스 본사 주소를 프랑스 제조 증거로 취급하지 않습니다. \`+ CV\`는 뚜껑 유무만 확정하고 유리 소재 여부는 확정하지 않습니다.
- 제품정보 표와 상세 원문 좌표를 화면에서 확인하고 CSV/JSON으로 내보낼 수 있습니다.
- P0는 **최종 아트웍 승인 판정이 아닙니다.** 로고·QR·문구별 합부 판정은 후속 단계입니다.

## 제품명 교차 검수

- **주 판정:** PDF 패키지 전면의 큰 제품명과 PDF 작업정보 `GAMME` 또는 `NOM GAMME`의 제품명을 비교합니다. 내부 접두어 `G7` 등은 제거합니다.
- 대소문자·구분 기호를 무시한 제품명 철자 일치 시 `OK`, 확실히 다른 철자는 `FAIL`, 위치를 찾지 못하면 `REVIEW`입니다.
- 파일명과 `PRODUIT`의 제품 유형·크기 비교는 참고 정보이며 주 판정에 반영하지 않습니다.
- 모든 추출 항목에 원본 페이지·좌표를 기록하고 PDF 영역 미리보기를 제공합니다.
- 전면의 주변 광고 카피는 추출만 하고, 승인 원문 없이 오탈자 `OK`를 선언하지 않습니다.
- `product_identity_checks.csv/json`을 ZIP에 추가합니다.

## PDF 전체 페이지 좌표 미리보기

- 텍스트 추출 후 파일·페이지를 선택하면 원본 PDF를 전체 페이지로 표시합니다.
- 국문 문단 또는 원본 줄, OCR 확인 문구, 곡선 문구, 전면 영문 제품명, GAMME 및 참고용 PRODUIT에 유형별 색상 박스를 겹쳐 표시합니다.
- 문구 목록에서 특정 항목을 선택하면 그 위치가 노란색으로 강조됩니다.
- 문단별 모드에서는 **원본 줄 각각의 사각형**을 사용하므로 문단 사이의 다른 언어 영역까지 덮지 않습니다.
- 페이지 회전과 렌더링 축척을 반영하며, 원본 추출 좌표를 변경하지 않습니다.
- Streamlit 선택 위젯을 조작해도 분석 결과가 사라지지 않도록 세션에 유지합니다.

## 작동 방식

- PyMuPDF로 PDF의 한국어 텍스트, 원본 블록·줄 번호, 좌표, 글꼴 크기를 가져옵니다.
- 읽을 수 없는 숫자·공백 등이 있을 때 해당 부분을 Tesseract `kor+eng`로 보완합니다.
- **문단 재구성:** 같은 PDF 텍스트 블록의 연속 줄은 좌표·줄 번호·글꼴 크기로 묶습니다. 서로 다른 블록이어도 보증 문구, 코팅 성능 문구, AI 생성 이미지 표시처럼 명확한 이어쓰기 패턴은 추가로 결합합니다. 취급 주의 사항, 분리배출 등 새로운 단락은 분리합니다.
- 원본 줄별 텍스트와 OCR 후보를 그대로 보존합니다. 문단 재구성은 표시용 후처리이며 실제 문구를 수정하지 않습니다.
- **곡선 제품명 결합:** 인접한 회전 텍스트 조각을 각도·좌표·글꼴 크기로 그룹화하여 `프라이팬`, `멀티팬` 등으로 이어 붙입니다. 기존 줄별 원문은 별도 보존합니다.

## 결과 다운로드

- `korean_paragraphs.csv/json/txt`: 문단별 정리 결과
- `korean_only.csv/json/txt`: 원본 줄별 한국어 추출 결과 및 OCR 후보
- `summary.json`: 파일별 요약

## 한계

- 곡선 글자는 각도·좌표가 인접한 조각만 결합하며, 비정형 배치에는 추가 검증이 필요합니다. 임의의 제품명을 추측하여 생성하지 않습니다.
- 문단 재구성은 원본 PDF의 동일 텍스트 블록을 우선 사용하며, 일부 확실한 블록 간 이어쓰기 유형을 지원합니다. 다른 비정형 레이아웃은 여전히 별도로 표시될 수 있습니다.
- OCR 복원 후보는 자동 승인된 문구가 아니며, 특히 숫자와 문장부호는 원본과 대조해야 합니다.
- 로고·QR 검출 및 검수 규칙 판정은 추후 구현 대상입니다.

## 데이터 보안

원본 회사 PDF, 승인 문구 Excel, 생성된 검수 결과, API 키는 저장소에 업로드하지 마세요. 업로드 PDF는 앱 프로세스에서만 처리하도록 설계되어 있으며 서버 배포 시 접근 통제를 별도로 고려해야 합니다.
